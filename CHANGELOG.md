- 2026-08-09 — A scheduled agent's report is a queue, and nobody is draining it: a recurring agent re-discovers the same finding every run and writes it up fresh, so a real defect acquires a rising number and becomes wallpaper. Each report is individually correct, which is why the pattern is invisible — the failure exists only in the sequence, and a reader who learns a paragraph never changes will miss the day it does. Hand the agent its previous output and ask for a diff (new / cleared / unchanged and for how long), and escalate anything surviving three consecutive runs as a named decision. - 2026-08-09 — A second opinion from the same model is a mirror: two instances of one model share the training, priors and blind spots, so the second arrives at the first one's answer by the first one's route and returns unearned confidence. For load-bearing calls ask a different vendor's model and treat cross-vendor agreement as the signal; a split locates where the question is genuinely open. Numbered questions, percentages, explicit bluntness; keep briefs and answers on disk. Two plumbing traps: a wrapper reading a fixed path reviews the wrong document forever, and a tool that appends piped input hangs on an inherited non-interactive stream. - 2026-08-02 — Driving a browser reads whatever the page is holding: browser tooling returns content that is not scoped to what you asked for. A script that enumerates a page's links to find one to click will return every link, and on an authenticated application the navigation is the content — a logged-in messaging app hands back the conversation list with message previews, straight into a transcript that persists and syncs. - 2026-08-02 — A probe that succeeds is not the call you are about to make: the reachability check before an API operation is naturally the cheapest call available, and a clean read makes access feel settled. But the scope that permits a read routinely does not permit a write, so the failure surfaces at the mutating call after the plan is committed, reading as an outage rather than a permission never held. The same trap has a network variant — an address reachable from one machine is not reachable from the box that runs the job. Probe with the operation you intend, same credential, same place. - 2026-08-02 — The index carries a pointer, not the procedure: a store too large to load whole is usually fronted by an auto-loading index of one line per topic, which is enough to know a rule exists and not enough to act on it. At the moment of the request the session holds a hint and no procedure, so it explores, guesses, or asks something already answered — and the reflex, writing another rule file, is how the store grew past readability in the first place. The fix is retrieval rather than authorship: a prompt-submit hook that injects the actual call sequence verbatim before reasoning starts, written as an order and measured for fire rate against real prompts. - 2026-07-31 — A self-graded status checklist (done/not done/deferred) can make doing nothing count as compliance: deferred is a formally valid closing state, so a turn that names the fix and defers it anyway still reads as compliant. - 2026-07-30 — A skill that asserts facts, written once and never re-checked: A skill is rarely just a procedure — it also carries claims about the world (which service is behind this, what the default is, how long it takes). Because a skill reads as authoritative, it gets trusted over the general project instructions, which are usually the file that actually got updated — so every estimate comes out wrong in the same direction. A stale skill is also wrong by omission: an endpoint list predating a feature makes a reader build a workaround for a solved problem. - 2026-07-26 — Hook registrations live in a file, and ordinary file operations can revert them: a settings file inside a version-controlled directory makes every routine git operation an operation on your enforcement layer, and a file sessions edit constantly but nobody commits can be months stale at HEAD. - 2026-07-10 — Waiting on a worker that already died: a delegated agent that stops with "I'll continue when X completes" has ended its turn — if X finishes without re-invoking it (or it dies mid-report), nothing resumes it and no error surfaces; the finished work sits orphaned while the delegating session waits for hours.
